# OpenRouter worker

Отдельный Go-сервис для асинхронных AI-действий. Сейчас registry содержит действие
`voice_transcription`, `answer_evaluation`, `candidate_report` и `candidate_feedback`; новые действия добавляются отдельными
handlers и типизированными job-таблицами.

Worker получает `interview.completed.v1`, сохраняет inbox и независимую durable job
для каждого голосового ответа, после commit делает RabbitMQ ACK. До четырёх runners
берут готовые jobs через `FOR UPDATE SKIP LOCKED` и lease. Голос скачивается через
Telegram `getFile` во временный каталог `0700`, файл создаётся с правами `0600`,
ограничивается 20 МБ и удаляется после каждой попытки.

Результат и собственный outbox фиксируются одной транзакцией. Публикуются:

- `interview.voice.transcribed.v1`;
- `interview.voice.transcription_failed.v1`;
- `interview.answer.evaluated.v1`;
- `interview.answer.evaluation_failed.v1`;
- `interview.candidate.reported.v1`;
- `interview.candidate.report_failed.v1`;
- `interview.candidate.feedback_ready.v1`;
- `interview.candidate.feedback_failed.v1`.

Transient-ошибки повторяются без ограничения с exponential backoff и jitter до 30
минут. Невалидный Telegram file, превышение 20 МБ и неподдерживаемое аудио получают
статус `permanent_failed`.

Worker хранит технические таблицы в схеме PostgreSQL `openrouter_worker`. Inbox
очищается через 30 дней, опубликованный outbox — через 7 дней, terminal jobs — через
90 дней. Транскрипции в backend автоматически не удаляются.

Локальные проверки:

```bash
GOCACHE=/tmp/hr-assistant-go-cache go test ./...
TEST_DATABASE_URL='postgres://...' go test ./...
```

Проверка ответа получает готовый текст и снимок ориентиров из события
`interview.answer.evaluation_requested.v1`. Общая схема и валидатор находятся в
`../shared/evaluation`, промпт — в `prompts/answer_evaluation.v1.md`. Модель задаётся
через `OPENROUTER_EVALUATION_MODEL` (по умолчанию `openai/gpt-4.1-mini`). Невалидный
JSON, несогласованный evidence или недословная цитата допускают до трёх попыток
(первый запрос и два повтора); счётчик не расходуется на сетевые ошибки.
Повторный запрос получает безопасную подсказку по причине нарушения: например,
цитата при `not_found` или отсутствие дословного совпадения. Причины сохраняются
в `last_error_message` и логах как фиксированные коды; исходные данные и тело ошибки OpenRouter не попадают в ошибки
или логи. После очистки заданий компактные `completed_evaluations` предотвращают
повторную обработку той же версии.

Docker-образ собирается из корня монорепозитория:

```bash
docker build -f openrouter-worker/Dockerfile -t hr-assistant-openrouter-worker .
```

Подробнее: [план и протокол проверки ответа](../docs/feature-answer-evaluation-plan.md).

Общий отчёт получает `interview.candidate.report_requested.v1`. Контракт и проверка
цитат — `../shared/candidatereport`, промпт — `prompts/candidate_report.v1.md`.
`OPENROUTER_REPORT_MODEL` задаёт модель отдельно (по умолчанию `openai/gpt-5.6-terra`).
Для Terra клиент не отправляет неподдерживаемый `temperature`; Structured Outputs
и обязательная поддержка параметров провайдером сохраняются.
Текстовые действия используют `internal/app/structured` для Structured Outputs,
безопасных ошибок, usage и отдельного лимита из трёх невалидных ответов. Временные
ошибки следуют общей политике backoff. `completed_candidate_reports` сохраняет
идемпотентность после удаления технических заданий; ключ — сессия и версия.

Ошибки отчёта сохраняют конкретную причину и путь поля в `last_error_message`
и логах, например `invalid_result:missing_evidence:criterion_scores[2].evidence`.
Путь использует индексы с нуля. Следующая попытка получает подсказку по этой
ошибке и заново формирует весь отчёт; результат проходит все прежние проверки.
В подсказку допускаются только фиксированные коды и пути из схемы, без текста
ответов, названий критериев или ответа провайдера. Числовая оценка, включая 0,
требует evidence внутри самого критерия; цитата в другом разделе её не заменяет.

Подробнее: [план общего отчёта](../docs/feature-candidate-scoring-plan.md).

При ручной пересборке отчёта backend сначала повторяет последние неудачные
проверки ответов и ждёт их завершения, затем фиксирует новый снимок для отчёта.
Успешные проверки не повторяются; прежний отчёт остаётся доступным. Повторные
запросы с одной наблюдаемой версией не создают дубликатов. В карточке неудачной
проверки показываются число завершённых попыток и понятная причина ошибки.

Если модель изменила только регистр букв в цитате, worker восстанавливает её из
исходного ответа при единственном совпадении. В отчёте поиск ограничен указанным
номером ответа. Слова, пунктуация и неоднозначные совпадения не исправляются.
После восстановления выполняется прежняя строгая проверка схемы и дословности;
backend также проверяет уже восстановленные цитаты без послаблений.

### Обратная связь кандидату

Backend публикует `interview.candidate.feedback_requested.v1` в той же транзакции,
в которой сохраняет успешный отчёт. Действие `candidate_feedback` использует
`OPENROUTER_REPORT_MODEL`, отдельный [промпт](prompts/candidate_feedback.v1.md)
и контракт `../shared/candidatefeedback`. Вход содержит первичные ответы и
текстовые выводы отчёта; числовые оценки и ориентиры HR в него не включаются.
Результат — `paragraphs` из 1–3 непустых строк, до 600 символов в каждой.
Вложенные переводы строк, в том числе Unicode-разделители, запрещены.
Backend повторно проверяет результат и соединяет абзацы пустой строкой.

Генерация имеет собственный счётчик попыток: максимум три невалидных ответа,
сетевые ошибки повторяются с общим backoff. Результат и Telegram outbox сохраняются
атомарно в backend, повторные события не создают новых сообщений. Таблица
`candidate_feedback` хранит статус генерации; статус доставки остаётся в
`telegram_deliveries`. `completed_candidate_feedback` предотвращает повторные
AI-запросы той же версии после очистки технических заданий. Успешная пересборка
отчёта повторяет только генерацию со статусом `permanent_failed`; готовый или
ожидающий фидбек повторно не создаётся. Рабочая база требует миграции `00004`
worker и `00015` backend; сервисы должны быть обновлены вместе с топологией.
