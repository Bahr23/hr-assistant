# План: итоговый отчёт по кандидату

Источник требований: feature-candidate-scoring.md от 7 сентября 2026.

1. Расширить агрегат вакансии: описание, критерии, версионируемый каталог из 10 шаблонов, атомарное сохранение и валидация.
2. Зафиксировать название, описание и критерии при старте интервью; показать описание в Telegram до старта.
3. Добавить версионируемый контракт отчёта, строгую схему, проверку цитат и серверный расчёт среднего/покрытия.
4. Запускать отчёт после конечного состояния всех обработок; сохранить вход каждой версии, идемпотентность, повторную сборку и предыдущий успешный результат.
5. Расширить API и интерфейс создания/редактирования вакансии и карточки кандидата.
6. Проверить ограничения, изоляцию HR, снимки, очереди, ошибки, повторную генерацию и интерфейс; обновить локальное приложение.

## Принятые решения

Критерии необязательны, выбираются вручную, имеют одинаковый вес. Описание показывается целиком (лимит 10 000 символов). Общий балл показывается при хотя бы одном оценённом критерии, всегда вместе с покрытием. При отсутствии критериев строится текстовый отчёт. История версий сохраняется технически; интерфейс показывает последний успех и состояние новой версии. Старые сессии не получают критерии задним числом: отчёт доступен вручную и отмечает отсутствие исторического контекста.

Критерии хранятся отдельной таблицей, результат и неизменяемый вход отчёта — типизированным JSONB. Полнота обработки определяется приложением по конечным состояниям. Любой числовой балл требует проверенной цитаты. Ошибка обработки сама по себе не означает нулевую оценку.

## Проверки

Завершены:

- Go: общая схема/цитаты/округление; backend и worker со всеми PostgreSQL-интеграциями.
- Проверены неизвестные и повторные ID, пропуски критериев, несовместимые статус и балл, выход за диапазон, отсутствие и подмена цитат, лишние поля, ограничение вопросов.
- Проверены снимки названия/описания/критериев/вопросов, конечные ошибки, конкурентные завершения, четыре одновременные пересборки, сохранение старого успеха, неизменность входа и ручной отчёт для старого интервью без критериев.
- HTTP + RabbitMQ + локальная имитация OpenRouter: создание и чтение каталога, атомарная валидация PATCH, изменение вакансии после старта, первичные ответы + промежуточный AI-разбор, общий отчёт, coverage, usage, повторная сборка и изоляция HR.
- Frontend: 26 тестов; TypeScript, production build и ESLint.
- Telegram: 15 тестов в штатном Docker-образе, включая полный текст 10 000 символов и кнопку старта только после последней части.
- В браузере проверены итоговый отчёт, нейтральное отсутствие данных, цитаты, выбор нескольких шаблонов, редактирование выбранного шаблона и сохранение.

Обнаружена и исправлена регрессия существующего PATCH-контракта: пустые defaults для необязательных полей могли затирать пропущенные поля. Теперь отсутствие поля сохраняет его значение; регрессия покрыта HTTP-тестом.

Сквозной тест использовал имитацию OpenRouter. Реальное качество выставления баллов моделью на профессиональном наборе интервью этим тестом не измеряется.
